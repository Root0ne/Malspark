### Fixed

- **A Sigma selection that can match alone holds a specific value, and a Sigma draft carries only the techniques that name what it selects (T-714).** Each selection of a Sigma draft can match alone, so `detection_signatures.selection_specific` takes out every value the benign-location catalogue calls every Windows host's (`benign_reason`, asked of the value as selected, a sandbox-recorded key or image included) and every `contains` value another selected value lies under or that is a longer spelling of another (the folder a selected file lies in), case and separators folded; a selection left empty is taken out, and a draft left with none is not built, its reason printed in the existing "No Sigma draft" line. Each value taken out of a draft that is built is kept on the rule's record (`values_left_out`), not printed. The builder and `drafts_not_built` read the one decision. A write a sandbox recorded under a key every installation has is selected by the key with the value's name and the program its data names: `sandbox_registry_ops` reads the value's name a write call carries (`ValueName`, `lpValueName`) into its row's new `value_name`, which fills `RegistryMod.value_name`. A path the table publishes whose file name alone is one Windows ships keeps its folders past the drive and the profile. A Sigma draft is tagged with a technique only where the technique's evidence quotes or roots name a selected value whole and delimited (quoted, in code marks, or as a path component), with a tactic only for a technique kept, and with no `tags` key when none is. The registry tool's answer gains `value_name` on a write's row; no other text a model reads changed. The YARA and Suricata drafts are unchanged.
