### Fixed

- **A Sigma selection that can match alone holds a specific value, and a Sigma draft carries only the techniques that name what it selects (T-714).** Each selection of a Sigma draft can match alone, so `detection_signatures.selection_specific` takes out every value the benign-location catalogue calls every Windows host's (`benign_reason`, asked of the value as printed, a sandbox-recorded key or image included, with a reason true of the value as stated) and every `contains` value another selected value lies under or that is a longer spelling of another (the folder a selected file lies in), case and separators folded; a selection left empty is taken out, and a draft left with none is not built, its reason printed in the existing "No Sigma draft" line. Each value taken out of a draft that is built is kept on the rule's record (`values_left_out`), not printed. The builder and `drafts_not_built` read the one decision. A write a sandbox recorded under a key every installation has is selected by the key with the value's name and what its data names: `sandbox_registry_ops` reads the value's name a write call carries (`ValueName`, `lpValueName`) into its row's new `value_name`, which fills `RegistryMod.value_name`, and two values written to one key are a row each. Every program and file path the data of a persistence payload or a written value names is read by `sandbox_report.command_line_paths` (now public, a quoted path read whole): a program of the sample's own is selected as the image; after a program Windows ships, each further path is selected in the field that records the data (`Details` in a registry event, `CommandLine` in a process creation); only a write names a program. A path whose cut form is a file name Windows ships keeps its folders past the drive and the user's own name (`Users\Public` kept), a long-path prefix is read off, and a path printed as such a name alone is never selected, with a reason that says so. A Sigma draft is tagged with a technique only where the technique's evidence quotes or roots name a selected value whole and delimited (quoted, in code marks, or as a path component), with a tactic only for a technique kept, and with no `tags` key when none is. The registry tool's answer gains `value_name` on a write's row, and a row for each further value written to the same key; no other text a model reads changed. The YARA and Suricata drafts are unchanged.
