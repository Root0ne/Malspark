### Added

- **A finished run records the environment it ran in (T-668).** The run summary carries an `environment` block, wherever the summary is stored, served and exported: the worker's host (operating system and release, machine type, processor model, and the kernel's logical processors and total memory, with the processors and memory limit the worker process itself may use where its control groups say), and per agent one row for each model it was built to send with — the configured model, a path-shaped one kept by its base name; the sampling parameters and thinking switches its provider adapter read off the request body the client built when the model was built, the statement that none was sent and the provider's default applied, or "not reported"; how many requests the platform changed a thinking switch of after that; the effort level with the setting it came from, or why none was sent; and how many recorded answers came from that place in the list, so a fallback that was never needed reads 0 — beside each model identifier the provider's answers named, a path-shaped one kept by its base name. The block also records the tools the run ran: one row per tool server or provider that served the run, saying whether its tools were offered to an agent, called by one or run by a triage pack step, with the name and version the server gave when attached and what each requirement its tools declare was on its host — a library's installed distribution and version, a rule set's file count and one SHA-256 over its files, a program's version where its tool declares how to ask it, else "not reported". The pack steps the worker runs itself have a row of their own. These facts come from the capability manifest every tool server already answers, which now carries them, read once when the server starts; a server with no manifest gives its name and version only. Each fact appears only where it was read, and one that was not is "not reported", never a statement that nothing was sent; a summary stored without the block reads as before. When a run summary is published with benchmark evidence, its model identifiers are left by the host and run-name rules and pass every other rule.

### Fixed

- **The model build log line states the sampling actually sent (T-668).** It used to print the temperature handed to the provider, which a model whose API or client library drops sampling parameters is never sent. The line now names the sampling read off the request body the client would send.
