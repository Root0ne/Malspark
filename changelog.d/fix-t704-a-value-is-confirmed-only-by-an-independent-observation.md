### Fixed

- **A value taken from the file's text is published only when an observation independent of that text confirms it (T-704).** A path, a registry key or a mutex the string sweep read is confirmed by what a sandbox watched, by what a persistence mechanism names, or by an entry an analyst cites whose declaration says it watched the sample or recovered the value (a sandbox or capture, a rule over its events, an emulator, a decoder, a hash resolver, a transform that ran a step, or any tool whose declaration states `observes`). A listing, a string search, a decompile, a byte read or an extractor reads the same bytes again and confirms nothing. A cited entry of a tool that declares no kind confirms, its reason names the tool, and the run summary counts such values (`undeclared_confirmations`). The decision is per entry and is recorded once at build time (`second_source_reads`), so the IOC table, the feed and the export decide alike. A path or a registry key the sweep cut out of a longer token of the sample is recorded as such (`cut_from`, never in a tool's answer) and is published only where an observation holds it as a whole token. A recovered name its tool spelled as a code identifier (a lower-case label, then a member beginning with a capital) is no hidden host, and where the strings listing is partial the "also a plain string" holdout reads the sample's text through the readers' boundary, bounded at the sample upload cap. Each refusal states its reason in its first clause.
