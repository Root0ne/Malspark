### Changed

- **The unread-functions question ranks by what the run ties to each function (T-565).** The functions on the path from a start down to a routine the analyst read come first; then the artefacts the function index states as each function's own (imports, calls through resolved slots, resolved hash names, strings it refers to, rule matches), plus those of the unread functions every chain of calls into which passes through it, compared by power of two; then the distance from where the code starts. Ties keep a stable order, and when more functions are unread than the question lists, its last 2 places go to the nearest of the rest by distance alone. Each listed function's reason gives those counts, the question says that a function's counts may include those of other functions listed, and the functions past the first 12 follow as bare addresses in rank order (at most 100, then how many more). At most 12 are given with reasons, the question is advisory, and an answer with nothing unread adds nothing to the turn.
