### Added

- **A claim's cited entry ids are checked against the ids the job issued (T-684).** Every id on an analyst claim's EVIDENCE line has to lie within the count of the job's evidence counter, which issues ids to every agent; one past it is asked about once per claim block (`isr.unissued_evidence`), whether or not the claim names a technique. An id another analyst's call took is the job's and is not asked about, and item ids are not read. A technique claim citing only such ids is asked the existing ungrounded-technique question, which names them. The finding follows `validation.feedback` like every other claim finding, and the replay of a stored run reads the count off the run's ledger. The further-detonation request reads the same decision.
- **Every entry id a composed report section writes is checked against the run's issued ids (T-684).** Besides the bracketed citations of its prose, each `ev_` id anywhere in a composed section's answer — a citing field, a command, flag, step or cipher record, bracketed or not — that the run did not issue is asked about once under the existing `report.citation_not_evidence`. Code spans and item ids are not read; a configuration or host-identifier row its own check already asks about for citing no entry is not asked twice, and the narrative's key findings keep their own check.
- **A technique id written in a claim's sentence gets the catalogue's questions (T-684).** An id the sentence names beside the claim's TECHNIQUE line is asked whether the ATT&CK catalogue holds it (`attck.unknown_id`) and whether it can apply to the sample's platform (`attck.platform_mismatch`), once per claim block and id, on a path that names the sentence. An id the sentence states as not asserted, withdrawn, dropped, not supported, not adopted, retired, deprecated or revoked after the id, or as withdrawn or retracted before it, is not asked where the sentence does nothing else with it: the statement ends its clause after at most a short declared tail ("by the scanner", "here", "as a label"), one more absent id or predicate, and a reason ("because …", or in brackets), and the id is the predicate's subject, not a parenthetical remark. An id the sentence negates is not asked either. An id the sentence states absent and then turns from or goes on about ("but", "yet", "however", "and the sample …") is asked, even where it also negates it. The reading is lexical; the sentence is not asked whether it describes the id. The question asks to correct the id or to say plainly that the technique is not asserted. A sentence id never marks the claim's own technique invalid. Only an analyst's claim sentence is read this way; a judge's map reason is read for the mapped id alone.
- **The entry ids a verdict names are checked against the ids the job issued (T-684).** An `ev_` id the judge's bundle names, in its assessment or any object, past the count of the job's evidence counter is asked about once (`verdict.unissued_evidence`), on every way the verdict round can end. An indicator's pattern and code spans are not read, and the finding follows `validation.feedback`.
