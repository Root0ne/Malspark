### Fixed

- **In a launcher run, a file the launcher's own process writes or dumps is the launcher's, and an archive member's copy is the platform's only at the member's place (T-694).** A written or dumped file names its task, and its writer is read among that task's processes. One every writing process of which is the script host running the generated launcher is listed with the launcher's facts (path, digest, writer) and not among the sample's files, unless a signature of that task shows another process acting on the launcher's process: then it stays among the sample's files, marked with the launcher's lineage as not established, and is counted (`launcher_unsettled_written_files`) with the rows naming no task; the launch statement gives both counts. Where a task states the parent of the process running the sample as a process it lists, the launcher's process is also an ancestor of a process of the sample's tree, so a script host the sample started outside its own tree is not the launcher's; where no script host naming the launcher is such an ancestor, no host is the launcher's there: the hosts' processes, flows and files stay in the sample's view marked as the launcher's lineage not established, and the attribution is stated as not established with that reason. A member's copy is the platform's only at the folder the archive was unpacked into joined with the member's path, holding the member's SHA-256 where the row states one, and never where a process of the sample's tree wrote it; a file with a member's SHA-256 elsewhere is the sample's, stated as a copy with both paths, one at the member's place with another SHA-256 is stated as the member changed, and one the sample's process wrote there is stated as written by it. A row stating no guest path keeps the reading by name or SHA-256 and is counted (`launcher_unplaced_member_files`). A run without a launcher carries none of these marks.
