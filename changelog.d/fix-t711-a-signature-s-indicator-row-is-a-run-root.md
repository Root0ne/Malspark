### Fixed

- **A sandbox signature's indicator row is a run root of the process it names (T-711).** Each indicator row a signature view or a signature item holds gives the root of the process that acted and of the one acted on, by the process's task and the report's own id, so a statement that names an injection's processes is a behaviour source for the technique. A statement picks a process by the number it writes after `pid` or after a field a sandbox reader declares names a process by its list's id, the report's id or the guest's pid; a number more than one process answers to picks none, and so does an id one listing holds twice in a task, by any number. A row that states no task is the process of its id in the one task that lists it, and names none where several tasks do. A process the report lists in more than one task is written with its task (`sandbox process 87 in task behavioral1`). A row naming no process the report settles says so; a signature with no indicator row names none; a process item at a place the listing does not hold (`proc:87.0`) names none.
