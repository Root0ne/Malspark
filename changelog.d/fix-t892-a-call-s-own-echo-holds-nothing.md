### Fixed

- **A call's own echo holds no value on the publish route or in the citation check's holder search (T-892).** A tool's answer may repeat the call it answers (a search's pattern, a lookup's path). One shared reading compares each text an entry was read in with nothing taken out against the same text without what repeats its call's arguments, both written the same way, so an entry nothing echoes never changes; the byte reading reads the same echo-free text. On the publish route a cited entry that holds a host value whole only in that echo is no holder — not for the answer, the published reason or the row's evidence ids — unless the rest of its text holds a spelling of the value at a place no letter, digit or `_` of the run around it touches, read decoded. A row refused so says that a cited entry holds the value whole only where its answer repeats what its call asked for, and, where the rest of that answer holds its text only inside a longer run, that too. The citation check no longer offers an entry that holds the value whole only in its echo while the rest of its text holds it only inside a longer run; an entry whose rest holds no spelling of the value (a search that found nothing) is offered as before.
