### Fixed

- **A launcher's Triage submission carries the analysis time where Triage reads it (T-701).** Triage does not apply `defaults.timeout` to a submission that names a `profiles` entry, so a launcher's submission ran for Triage's own default whatever `sandbox.triage.analysis_seconds` said. With no profile configured, the launcher's pick entry now embeds a profile carrying the time (`profiles[0].profile.timeout`), and `defaults.timeout` is kept beside it. A plain submission, a submission with no time set and one that names a configured profile (whose stored profile's own time applies) are sent exactly as before. A refused submission names the fields the time was sent in, and where a task is granted less time than was asked, the run's limitations say so on every path.
