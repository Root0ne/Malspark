### Added

- **What a run could not do is measured once and printed from that record (T-601).** Before the
  report's prose is written, the report node reads the limitations inventory off the ledger and
  stores it on the report (`limitation_inventory`): each failed call with the later calls that
  redid it by the run's one redo map, else the later calls for the same address, and how many
  entries were trimmed to the budget; how many routines have listed code and how many routines
  they call have none, with the first of those on the path from a start the answers state; the
  tools the run could not offer with the reason it recorded, the tools the job's configuration
  withheld and every other limitation it recorded, read again by the same split once the
  composer and the agreement question have recorded theirs; whether a sandbox recorded the
  sample and each section of the sandbox report's index, read by the declared kind
  `sandbox_sections`; the window and packet count of the capture an entry of the declared kind
  `pcap` read; and each open question, marked where every routine it names has listed code, and
  "after it was filed" where each listing came after its analyst's last entry. The mark is a
  fact: whether the listing closes the question is the model's reading.

### Changed

- **Section 11 of the analyst report prints the measured list, then the paragraph (T-601).**
  Under "What the run could not do (measured):", one line per row that states a limit, at most
  seven, each from a fixed template, citing the entries it rests on where it has any: failed
  calls no later call redid and entries trimmed to the budget, routines called with no listed
  code, tools not offered and the count of other recorded limitations, sandbox sections
  unavailable or not in the sandbox report as read (or no sandbox observation), the capture
  window, the open questions counted by reason in plain words, and the analyst claims not
  discussed. A tool's name, a sandbox section's name and a recorded reason are escaped as the
  evidence bundle escapes them. A failed call a later call redid, the tools withheld by the
  job's configuration and the sandbox sections that hold items print in the evidence bundle's
  limitations section, which lists every row of the inventory under "Measured limitations". The
  partial-evidence count, the redone calls and the trimmed count in the bundle's evidence bounds
  read the same record. An address only the list names does not keep a sentence out of the
  report's other sections or its appendix. A report stored without the record renders as it
  did.
- **The limitations' writer is shown the list as printed (T-601).** Its bundle holds the
  printed lines, every other row but the marked questions' (shown once, with their listings),
  and the open questions split into those whose routines all have listed code and the others,
  each with its analyst, reason code and citations. It is asked to restate none of the rows,
  nor the line counting the claims not discussed that may close the printed list, to write only
  what they do not state, to say what a row leaves open citing the entries that show it, and to
  read a listing before calling its question open.
- **The agreement question is shown the inventory wherever the limitations paragraph stands
  (T-601).** Its rows are facts `inv.1` onwards: each failed call with the calls that redid it,
  every other row in its own words, and each open question filed on a failed call or a missing
  tool. They replace the failed-call, tool, recorded-limitation and open-question facts that
  were shown only where a sentence of the paragraph was held to the failed calls. Which
  passages are held, and the checks, ends and refusals the round applies, are as before: where
  the paragraph is held, a refusal that lists the facts speaking of a sentence names the `inv.N`
  rows among them: in place of the facts they replace, and beside them for a row that replaces
  none (the capture, the sandbox, the code read); elsewhere the rows speak of no sentence.
