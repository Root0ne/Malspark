### Added

- **A host value the analysis states is exported when code finds it whole in an entry the row cites (T-566).** The report model types each host identifier with a closed vocabulary (mutex, file path, file name, folder, registry key or value, scheduled task, service, named pipe, alternate data stream, string, template) and says whether the sample creates or writes it, reads or checks it, or the evidence does not show. The platform exports a row as source `analysis` on `/iocs`, MISP and, for a mutex, a file and a registry key, STIX only when the value is found whole in a cited ledger entry, holds no format placeholder, is not a value every Windows host holds (a declared catalogue of known folders, system programs, registry keys and task-definition words, and the sandbox's copy of the sample), is created or written, and the verdict publishes. Section 9 prints the rule's answer beside every identifier. A generic name carries a false-positive note. Reports stored before the typed kinds keep their IOC tables; their rows are refused with that reason.
- **A Sigma draft selects only whole values a log records, one draft per log source (T-566).** A file and a folder the analysis states are selected in `file_event`, a stream in `create_stream_hash`, a scheduled task in Security event 4698, a service in System event 7045 and a named pipe in `pipe_created`. A sandbox signature's description is no longer a selection (it is named in the rule's description), no selection value is cut, a generic name never forms a selection, and a run left with no value to select on has no Sigma draft and says why in the report and the console.
