### Added

- **`validation.feedback` can record every finding without asking the agent to correct it (T-672).** The default, `feed_back`, is unchanged: a check's findings are put to the agent that wrote the answer in one correction turn. `record_only` runs every check and records every finding as not asked, and sends no correction turn and no follow-on question to the analysts, the judge (its verdict and its technique question), the composer, the narrative, the question round or the section agreement: each answer stands as written. An answer that could not be read (no claim parsed, cut at the output cap, not JSON, outside its schema, its claims repeated) is asked again in both modes, through one declared code set. What the platform does afterwards with a finding left standing, and every integrity guard, is the same in both, so a run in each mode shows what the correction turns change. A record-only run says so in `run_summary.validation.feedback` and among its operator choices; a run in the default carries neither. The setting is in the catalogue and imports through a settings document.

### Fixed

- **An analyst's finding that was never put to it stays marked not asked in the run summary (T-672).** The judge node rebuilt the analysts' findings from the state channel without their `asked` flag, so a row the analyst was never shown (a describe finding standing alone, no time left for the turn, a failed turn, a finding the retry raised first) came back into `run_summary.validation.unresolved` as asked and kept, and a stopped run's summary said the same. The row now keeps `"asked": "false"`, as the replay of the same run already wrote it; this changes the summary of a default run that has such rows.
- **The judge is no longer told an analyst kept a technique claim after being questioned when it was never asked (T-672).** The technique note in the judge's verdict prompt listed every platform mismatch and weak alignment left on an analyst's answer as a claim "the ATT&CK check questioned and the analyst kept", including the ones never put to the analyst (no time left for the turn, a failed turn, or `record_only`). Those are now listed under their own NOT ASKED heading, as the function-claim rows already were, in both modes; a default run whose rows were all asked gets the same note as before.
- **The STIX export no longer gives a reason the run record does not hold for a question the judge was not asked (T-672).** An unpublishable credit, or a malware object without `is_family`, the judge was never asked about was recorded as having "first appeared in an answer no turn was left to question"; the export of a stored run is rendered again later, under whatever settings are then live, and `record_only` asks nothing for another reason. The sentence now says only that the judge was not asked about it, in both modes.
