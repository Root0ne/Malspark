### Added

- **`validation.feedback` can record every finding without asking the agent to correct it (T-672).** The default, `feed_back`, is unchanged: a check's findings are put to the agent that wrote the answer in one correction turn. `record_only` runs every check, records every finding as not asked and lets each answer stand as written. It stops the analysts' validation turn with the questions it carries (callees not read, decompiled routines no claim describes, exit branches) and the question about what a kept retry left out, the judge's verdict retry, the describe check's questions and text in the judge's technique question, and the correction turn of the composer, the narrative, the question round and the section agreement. The rest of the judge's technique question (claimed techniques the bundle lacks, techniques named only on a finding or by a call) and each stage's own question are still sent. One criterion decides what is asked in both modes: a code whose finding, left unasked, would lose the agent's own content to a fallback because the answer or a part of it could not be read, or is absent where the stage then substitutes a fallback of its own (not JSON, cut at the output cap, outside its schema, no claim parsed, claims repeated, a claim block with no readable confidence or technique line or under DISPUTES, an unreadable verdict word, severity rating or assessment part, a missing assessment or a verdict it does not state, a judge object of no known type, an id two objects share, an indicator whose pattern the STIX grammar cannot read). What the platform does afterwards with a finding left standing, and every integrity guard, is the same in both; the judge's verdict prompt still receives the analysts' findings, and an indicator the sandbox attributes to no flow of the sample stays out of the exports because the question that could publish it is not asked. The configuration page says how to compare a run in each mode. A record-only run says so in `run_summary.validation.feedback` and among its operator choices; a run in the default carries neither. The setting is in the catalogue and imports through a settings document.

### Fixed

- **An analyst's finding that was never put to it stays marked not asked in the run summary (T-672).** The judge node rebuilt the analysts' findings from the state channel without their `asked` flag, so a row the analyst was never shown (a describe finding standing alone, no time left for the turn, a failed turn, a finding the retry raised first) came back into `run_summary.validation.unresolved` as asked and kept, and a stopped run's summary said the same. The row now keeps `"asked": "false"`, as the replay of the same run already wrote it; this changes the summary of a default run that has such rows.
- **The judge is no longer told an analyst kept a technique claim after being questioned when it was never asked (T-672).** The technique note in the judge's verdict prompt listed every platform mismatch and weak alignment left on an analyst's answer as a claim "the ATT&CK check questioned and the analyst kept", including the ones never put to the analyst (no time left for the turn, a failed turn, or `record_only`). Those are now listed under their own NOT ASKED heading, as the function-claim rows already were, in both modes; a default run whose rows were all asked gets the same note as before.
- **The judge's note on function claims never asked no longer gives a reason (T-672).** Its NOT ASKED heading said no turn was left to ask on, which is false in `record_only`, where nothing is asked; it now says only that the analyst was never asked about them, in both modes, so a default run's note is shorter by that clause.
- **The STIX export no longer gives a reason the run record does not hold for a question the judge was not asked (T-672).** An unpublishable credit, or a malware object without `is_family`, the judge was never asked about was recorded as having "first appeared in an answer no turn was left to question"; the export of a stored run is rendered again later, under whatever settings are then live, and `record_only` asks nothing for another reason. The sentence now says only that the judge was not asked about it, in both modes. Likewise an indicator the sandbox attributes to no flow of the sample, in a stored run whose own `validation.feedback` is `record_only`, is no longer said to have been written in the judge's last answer with no turn left to ask it: it says the judge was not asked about it with this fact, read from that run's summary; a default run's wording is unchanged.
