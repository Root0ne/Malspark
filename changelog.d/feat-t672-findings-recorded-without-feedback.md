### Added

- **`validation.feedback` can record every finding without asking the agent to correct it (T-672).** The default, `feed_back`, is unchanged: a check's findings are put to the agent that wrote the answer in one correction turn. `record_only` runs every check and records every finding as not asked, and sends no correction turn and no follow-on question to the analysts, the judge (its verdict and its technique question), the composer, the narrative, the question round or the section agreement: each answer stands as written. An answer that could not be read (no claim parsed, cut at the output cap, not JSON, outside its schema, its claims repeated) is asked again in both modes, through one declared code set. What the platform does afterwards with a finding left standing, and every integrity guard, is the same in both, so a run in each mode shows what the correction turns change. A record-only run says so in `run_summary.validation.feedback` and among its operator choices; a run in the default carries neither. The setting is in the catalogue and imports through a settings document.
