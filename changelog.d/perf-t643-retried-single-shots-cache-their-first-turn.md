### Changed

- **On Claude, a report section's retry reads its first turn from the prompt cache (T-643).** A report section is asked once and, where its answer breaks a rule, asked again with the whole first turn, that answer and the question. The section's first request carries a cache breakpoint at the end of its first turn, besides the one on a head it shares with other sections, so the retry reads that turn from the cache where it used to write it again or send it uncached. That breakpoint always asks for five minutes, whatever the cache lifetime setting: its only reader is the retry, seconds later. The text and order of the turns and every other request field stay the same; a first turn sent as one string is sent as one text block with the same text; no request carries more than four breakpoints. A cut answer's retry, which asks its question at the end of the first turn, carries no such breakpoint, and every other call sends the same request as before. Providers that cache a prefix on their own send the same request as before.
