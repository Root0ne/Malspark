### Changed

- **A composed text that names the code of a check an analyst's claim states is asked for what the check tests (T-580).** A claim clause states a check when code fails, exits, aborts, stalls, terminates, quits, halts, stops or bails out, returns failure, a null or a number, or calls an API whose name opens on Exit or Terminate (after a native prefix), on a condition; or, the condition first, on a condition comparing with a number. The check's code is the last code location the clause names before its outcome, with the code its condition names (an address a slot, size, flag or other datum noun governs, or one written beside a constant's name, is a value, not code); a clause naming none that points back takes the code of the sentence before it and the last function that sentence calls, never one written only as an argument inside another call's brackets (`IsWow64Process(GetCurrentProcess())` calls IsWow64Process); a claim whose clauses name no code falls back to the code it names. What the check tests are the functions the clause calls from its subject on (an API-style name written only as another call's argument is none) and the numbers its condition compares with (comparison words and signs, "equals", "is not", "returns", an "or higher" close, a "+0x194" field offset); a 0, 1 or -1 after a bare "is", "returns" or "==" with no counted noun before it ("the processor count is 1" is one) is a truth value, and a number joined to a word by a hyphen is part of it. Where the execution flow, a functionality or command-and-control subsection, or an ATT&CK procedure (held to its own technique's claims) names that code, and its texts naming it leave out any of those values, the section is asked once to carry them where it describes the check, or to say why the evidence does not hold them; a text that names the code for another reason is kept as it is. In a prose body a sentence naming code is read with the sentences after it up to the next one naming other code. A number is carried in any base or as a small number word wherever it stands in those texts, so a number written there for another reason carries a check's too. A question on the same text and code that asks for no more than another is asked once, and a question names at most eight values and counts the rest. A kept text stands, with the finding recorded (`report.value_not_carried`); nothing is marked in the report. The replay runs the check over each stored section with the claims its bundle shows it.
