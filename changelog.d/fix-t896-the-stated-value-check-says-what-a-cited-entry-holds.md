### Fixed

- **The stated-value and cited-id checks read a cited entry's bytes, and say what was searched and what a cited entry holds (T-896).** A table row's stated value, and a row's id, are also held by a cited entry whose text writes them as bytes — the citation check's one byte reading, outside the echo of the entry's own call and under the platform's one chance bound — asked of each cited entry directly; a read that returns the first bytes of a longer string holds what it returned, as text cut at a chosen length does. In that reading a run equal to the bytes of a call argument followed only by NUL bytes, in the single-byte or the two-byte spelling, is the call's echo, and an entry's decoded byte runs are read once. The stated-value question says of a row's value, or of each span no cited entry holds, what was found: not found as a whole value, read as written and as the bytes the cited entries write where the byte reading takes the value (no number alone, nothing under three characters) and a byte run had a place to hold it, a holding chance explains said as such; only inside a longer run of text, with the run, whatever its length, spans beyond the listed ones counted, and then the ends such a value allows (keep the row where the value is one of several strings joined in the run, write the token where the longer token is the value, otherwise cite another entry or leave the row out); one or two characters the check reads as a number, which it never reads alone. It never says a span is in none of the cited entries. The cited-id question names the byte reading the same way, and says of an id read as a number that none of the cited entries writes it as a compared operand. A host identifier the export refuses because no cited entry's text holds it whole, while a cited entry's bytes do, is refused with words saying that the entry writes its whole value only as bytes, which the export does not read as a host value; the decision is unchanged.
