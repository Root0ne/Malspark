### Fixed

- **A Triage task report's DNS and HTTP requests are read under every name the report writes them under (T-693).** A question and its answer on one row (`domain_req`/`domain_resp`, `web_req`/`web_resp`) and each on a row of its own (`dns_request`/`dns_response`, `http_request`/`http_response`), an answer joining the first open question of its flow and index, fill the same DNS, HTTP and domain rows; headers are read as a mapping or as `Name: value` lines. A request row of a kind the reader does not read is kept whole in a `task.network.requests.<kind>` channel, counted by its rows, for at most 16 kinds of names up to 64 characters per task; the rows of further kinds join the channel of rows of no kind, labelled with how many kinds were folded into it. An answer with no request is kept and counted the same way. Each reader writes the process a flow or a request names under one key (`platform_process`), in one text form, read from the field its format states it under (a mapped format names its own through `field_names`); an id of a type that cannot be one is not stated. An HTTP request takes the process facts of the flow it rode on, of every flow a task lists under that id; a DNS request takes none, its flow being the guest's resolver. One rule decides an address, a name and a URL: a value is the sample's when one of its records came from the sample's tree, and another lineage's (another process, the launcher's, one the report does not list, or a disputed one) only when every record names a process of another lineage, and is then not published as observed from the sample, the answer saying whose it is; a record naming no process leaves the value as decided without one. A name's records are its HTTP requests, the DNS requests that name their own process and the flows to the addresses it resolved to. A URL on a withheld name is published when the judge kept its host after being asked with the fact. A dropped file's guest path is shown where the reader declares the field holding it.
