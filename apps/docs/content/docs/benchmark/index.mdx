### How a fact is scored

Each of the {run.items} facts gets one verdict:

| Verdict | Meaning |
| :-- | :-- |
| Found | The report body states the fact, with its purpose right. |
| Partly | The report body states part of the fact, or states it with the wrong purpose. |
| Partly, from the evidence bundle | The fact appears only in the evidence bundle that ships beside the report, bound to the routine it comes from, and not in the report body. |
| Missed | The report does not state the fact. A string that only hints at a behaviour counts as missed. |
| Wrong | The report states the fact in a way the analyses contradict. |

An item is scored whole: the key fact and the specifics added to it count as
one fact, so a specific the report states only in part, only in the evidence
bundle or not at all makes a found item partly. The scorer checks every verdict
against the run's stored evidence ledger, not only against the report text.
Every item drawn or sharpened after the run was scored by two independent
scorers. In the completion pass their verdicts were identical on every item;
for the items drawn before it, the lower verdict stands where they differed.

### Beyond the key

A fact counts as **beyond the key** when all three hold:

1. The report body states it, and the run's own ledger proves it: a tool
   answer, a decoded string, a sandbox record or a decompile, cited by its
   `ev_` id.
2. No item of K1 to K11 holds it. Where an item holds part of it, the fact is
   worded to what remains, and it counts only if more than addresses remains:
   a named API, value, string, structure or step that the key does not ask for.
3. Nothing contradicts it.

A wrong claim, or one the evidence does not prove, is never counted. It is
listed separately and left out of the total.

### Keeping the run honest

- **The run is blind to the key.** None of the eight analyses is given to the
  agents, and the run starts on {run.memory}, so nothing learnt from another
  run of the same sample reaches it.
- **Nothing is tuned for the sample.** The run used the all-tools team with
  the model, effort and sandbox listed under Setup, and nothing was set for
  this sample. The [reference configuration](/examples/profiles/all-tools-reference-run.json)
  carries the all-tools team as it ships and the model and effort the run
  gave each agent.
- **Blind A/B scoring is available.** When two runs are compared, the
  [blind scoring](/docs/blind-scoring/) tool hides which report came from which
  run until the scorer has finished. This page scores a single run, so it has
  no arm to hide.

## Limitations

- **One sample, one run.** No variance is measured. A rerun can move a
  borderline fact between found and partly.
- **One scorer for the plain core facts.** The project scores its own runs.
  Every verdict quotes the report sentence it rests on and is checked against
  the ledger, but the scorers know which run they are reading. The core facts
  that carry no added specific, {origins.core} of them, were scored by one
  scorer; every other fact was scored by two independent scorers.
- **A family well described in public.** The reference reports exist because
  the family is well known. A new family has no key to score against.

## Reproducing the run

<Steps>

<Step>

Start a stack and connect the model and the sandbox, as in the

</Step>

<Step>

Import the [reference configuration](/examples/profiles/all-tools-reference-run.json),

whose long-term memory is empty:

```json

  "sample_id": "<the sample's id>",
  "config": {"profile": "all_tools", "ignore_earlier_runs": true}
}
```

</Step>

<Step>

Score the stored report against the {run.items} facts of the key, fact by fact,
and check each verdict against the ledger
(`GET /api/v1/jobs/{job_id}/evidence`).

</Step>

</Steps>
