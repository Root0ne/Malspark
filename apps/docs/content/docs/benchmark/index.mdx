what expert human analysts published does it find, does it get anything wrong,

The key was drawn in two steps. Its 57 core facts were fixed from the first
three analyses, Bitsight, Elastic Security Labs and Proofpoint, before the run.
After the run, 18 facts were added, and the wording of 14 core facts was
sharpened, from the five further analyses, by a reader who had not seen the
report. The agents see none of the eight analyses. The facts are sorted into
eleven groups:

- **K1 to K10** hold the {run.items} scored facts: identity, execution flow,
  anti-analysis, identifiers, persistence, command and control, commands,
  discovery, indicators and ATT&CK techniques.
- **K11** holds the analyses' detection content: their YARA, Suricata and
  Sigma rules and hunting advice. It is not scored. It is used only to decide
  what counts as beyond the key.

Build-specific values, such as the C2 domains, the group name and the RC4 key,
are checked for consistency with the analyses, which describe the family
across many builds.

### How a fact is scored

Each of the {run.items} facts gets one verdict:

| Verdict | Meaning |
| :-- | :-- |
| Found | The report body states the fact, with its purpose right. |
| Partly | The report body states part of the fact, or states it with the wrong purpose. |
| Partly, from the evidence bundle | The fact appears only in the evidence bundle that ships beside the report, bound to the routine it comes from, and not in the report body. |
| Missed | The report does not state the fact. A string that only hints at a behaviour counts as missed. |
| Wrong | The report states the fact in a way the analyses contradict. |

The scorer checks every verdict against the run's stored evidence ledger, not
only against the report text. The added and sharpened facts were scored by two
independent scorers; where they differed, the lower verdict stands.

### Beyond the key

A fact counts as **beyond the key** when all three hold:

1. The report body states it, and the run's own ledger proves it: a tool
   answer, a decoded string, a sandbox record or a decompile, cited by its
   `ev_` id.
2. No item of K1 to K11 holds it.
3. Nothing contradicts it.

A wrong claim, or one the evidence does not prove, is never counted. It is
listed separately and left out of the total.

### Keeping the run honest

- **The run is blind to the key.** None of the eight analyses is given to the
  agents, and the run starts on {run.memory}, so nothing learnt from another
  run of the same sample reaches it.
- **Nothing is tuned for the sample.** The team and its prompts are the
  importable [all-tools team](/examples/profiles/all-tools.json), unchanged;
  the model, effort and sandbox are the ones listed under Setup, and nothing
  was set for this sample.
- **Blind A/B scoring is available.** When two runs are compared, the
  [blind scoring](/docs/blind-scoring/) tool hides which report came from which
  run until the scorer has finished. This page scores a single run, so it has
  no arm to hide.

## Limitations

- **One sample, one run.** No variance is measured. A rerun can move a
  borderline fact between found and partly.
- **One scorer for the core facts.** The project scores its own runs. Every
  verdict quotes the report sentence it rests on and is checked against the
  ledger, but the scorer knows which run it is reading. The 57 core facts were
  scored by one scorer; the added and sharpened facts were scored by two
  independent scorers, and the lower verdict stands where they differed.
- **A family well described in public.** The reference reports exist because
  the family is well known. A new family has no key to score against.
