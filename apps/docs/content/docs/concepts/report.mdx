The report is written by the reporter agent from the claims in force, the
judge's verdict and the ledger. It reads like a professional malware report.
The difference is that every statement in it can be traced to the tool call
that proves it.

## Sections

| Section | What it holds |
| :-- | :-- |
| 1. Executive summary | The key findings, each with its citation, and the verdict. |
| 2. Introduction and scope | What was analysed, with which tools, and what was not available. |
| 3. Sample metadata | Hashes, file type, size, signature, sections, imports. |
| 4. Execution flow | What the sample does, step by step. |
| 5. Functionality | Obfuscation and anti-analysis, API resolution, persistence, discovery, payloads. |
| 6. Command and control | Protocol, endpoints, configuration, commands. |
| 7. Conclusion | What the evidence supports, and how firmly. |
| 8. Detection | Indicators, detection rule drafts, hunting guidance. |
| 9. Recommendations | What a defender should do. |
| 10. MITRE ATT&CK mapping | Each published technique with its evidence, and the techniques the judge dropped, with why. |
| 11. Limitations | What the run could not establish, and why; then one line on what left the machine: for each kind the run's record places outside it or cannot place (model requests, lookups with what they were asked, sample uploads, tool calls, enrichment questions, tracing), who received it and how many times (or that no answered call is recorded), and, where the record does not place a receiver, that where it runs is not recorded (a receiver whose host the record names) or that its destination is not recorded; the enrichment questions name the hosts the record says they may reach. The calls per role and the rest of the record are in the evidence bundle. |
| Appendix | The detection rules in full, analyst statements that add detail, references. |

Where no sandbox ran, the report says so in one sentence instead of printing
empty tables.

Note how the report keeps two kinds of fact apart: what was *read from code*
and what was *observed* in the sandbox. Every statement says which it is.

## What the code checks

The reporter writes; the code checks. Before the report is stored:

- every citation must name an entry that exists and holds the value the
  sentence states;
- the closing sections, the Conclusion and the Limitations, are held against
  the body and the ledger, so a "not established" sentence cannot contradict a
  section that establishes the fact. A closing sentence, a value cell or a
  summary bullet the reporter keeps stays only on the quoted words of a source
  that state the same; where the quote stands word for word in a section 5
  passage and is refused only by the two word tests (it holds too few of the
  words before the sentence's negation, or none of what a denied item is), the
  one sentence of that passage holding the whole quote, in whole words, is
  printed in its place, with its citations, and the run records the sentence it
  replaced (`agreement.kept_in_source_words`). That sentence is moved only where
  it reads as prose on its own: not a list item, a table row or a heading, not
  opening on a word that points to the sentences before it ("It", "Its",
  "These", "Which"…), and not one the round itself leaves out or changes;
  otherwise the closing sentence is left out;
- a sentence of a section the report models wrote is read against the
  judge's decision as the run records it (the verdict, the family or none, each
  technique published or dropped with the judge's reason): the decision only
  leaves a sentence of section 5 or of a closing section out, with the reason,
  and never keeps or rewrites one;
- an absence sentence ("no file was written") is held against the ledger;
- an indicator is published only with a reason, and the reason is printed
  beside it in the IOC feed and the detection drafts.

A failed check goes back to the reporter with a [validation
code](/docs/concepts/validation/) and one turn to fix it. A finding first raised
by the answer to that turn had no turn left, and the run summary records it as
not asked; in the agreement round a finding counts as asked where the sentence it
is about was asked about, whatever rows carried it. A problem the reporter does not fix stays visible in the run summary,
with each sentence left out or replaced recorded whole.

One rule says where a sentence ends, for the agreement round and the analyst
report alike: a period ends no sentence where it closes a run of two or more
single letters each followed by a period (e.g.), or sits inside a number (1.2);
every other period a space follows ends one, a closing quote or bracket after it
read past, and a closing mark of emphasis (`**`, `_`) only where it closes
emphasis opened earlier on its line and leaves none open after it (a wildcard's
`*.*` closes nothing). A keep
or a drop that copies a whole field answers each of its sentences exactly as the
same answer given sentence by sentence would. The analyst report
leaves a sentence a check flagged out only
where it stands whole (a sentence, a list item's or one in emphasis among them,
or the whole of a table cell), never out of
another sentence that names the same value, and each section ends with a line
counting the sentences, bullets and cell sentences left out of it, if any; the
evidence bundle lists each with the reason.

## The evidence bundle

Beside the report sits the evidence bundle, as HTML and JSON
(`malspark-evidence-bundle/1`). It prints every section as the report does,
every note with its entries, and an index of every ledger entry: agent, tool,
source and outcome. A reader with only the bundle can check every citation.

## Formats

The same report is served as Markdown, HTML, PDF, the full JSON document,
STIX 2.1, an ATT&CK Navigator layer, an IOC feed and detection drafts. See
[Reports and exports](/docs/usage/reports-and-exports/).
